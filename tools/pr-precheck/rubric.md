# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Every hunk in the diff (its file and what it changes) read against the plan's stated change, Files, Not-in-scope lines, and deviation notes in the plan or description | Pass if every hunk serves the planned change or a recorded deviation, and every change the plan commits to is present in the diff or explicitly deferred. Fail if any hunk adds behavior, a new option, flag, or setting, a rename pass, or a rewrite in a file or area the plan never names or explicitly scopes out, with no deviation note; or if a planned change (code, docs, test) is missing with no deferral. Tests, changelog or whatsnew entries, and fixtures that exist to test or record the planned change are in scope. | required |
| description-matches-diff | Each factual claim in the PR description ("implements the plan exactly", "no other changes", "docs updated", "tests added", files touched) read against the diff and commit list | Pass if every claim the description makes about what changed is visible in the diff. Fail if the description claims something the diff does not contain (docs updated, a test added) or asserts fidelity ("exactly as planned", "no functional changes outside X") that the diff contradicts. A terse description that claims little passes. | required |
| decisive-evidence | The test-evidence section (and any before/after in the description) read against the plan's test plan and the repro steps | Pass if the evidence re-runs the plan's primary repro (the failing path the issue reported, with the same inputs or fixture) and shows its observable after, paired with an observable before or the repro's recorded before, and every other failure mode the plan's test plan names is addressed with a stated result (output, a named passing test, or a specific observed outcome). Fail if the primary repro's evidence is a claim without observable output ("tested locally, works now", "verified on my machine"), if it exercises only a control or an unchanged path, or if a failure mode the plan's test plan names is never mentioned in the evidence. | required |
| repo-checks-run | The test-evidence section read against the repo-facts block's stated test or check commands and the plan's test plan | Pass if the repo's own suite or stated checks (cargo test, yarn test, make test, zig build test, pre-commit, go test) are shown run with an outcome, or a failing or unavailable check is reported honestly with its reason, or an added regression test is shown passing. Fail if no repo check or test run is reported at all. A suite result alone never satisfies decisive-evidence. | required |
| reviewable-diff | Every added and removed line in the diff, plus the commit list | Pass if every hunk is part of the fix, its tests, or a record the repo asks for. Fail if the diff carries debris: debug prints (eprintln, println, console.log, dbg!) left in, commented-out code or earlier attempts, dead functions (including ones behind allow(dead_code) or named unused), stray TODOs, re-indentation or formatting churn, blocks of identical lines removed and re-added with nothing changed in the block, or import restructuring the fix does not need. Lines of the same statement as a real change (a multi-line call where one argument changed) that the diff shows as removed and re-added are not churn. Debris that is also out-of-plan scope fails both checks. | required |
| template-and-asks | The PR title and description read against the repo-facts block's "pull requests:" line: template sections, checklist items, and contribution asks (closes/fixes #N line, changelog or whatsnew entry, type-of-changes, Problem/Solution) | Pass if every section or checklist item the repo states is present with real content, and any file the template requires (changelog, whatsnew entry) appears in the diff. Pass vacuously when the repo states no template and no PR asks. Fail if a stated template section, required checklist, issue-link line, or required changelog/whatsnew entry is visibly absent. Asks met in substance under different wording pass. | required |
| ai-disclosure | The PR description read against the repo-facts block's "contribution policy" line (CONTRIBUTING.md, AI_POLICY.md). Treat every package as AI-assisted work. | Pass vacuously when the repo states no AI policy. When the repo states an AI policy that requires disclosure or own-words text, pass only if the description contains a disclosure meeting it. Fail if a stated disclosure requirement is unmet. | required |
| honest-shortfall | Deferrals, limits, and deviation notes in the plan and the description | Pass if any part of the issue the PR does not fix is named as deferred in the plan or the description, or vacuously when the PR delivers everything the plan promised. Fail only if the description presents the PR as a complete fix while the plan or diff shows a part left out. | preferred |

## Verdict rule

Accept if and only if every required check passes. Preferred checks never change the verdict; they appear in the summary only. An `unclear` grade on a required check counts as fail, because a claim that cannot be verified from the package means the PR isn't ready to submit. An honestly disclosed and deferred shortfall isn't a fail: grade against what the plan, with its deviation notes, promised, not against the whole issue.
